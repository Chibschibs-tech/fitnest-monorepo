# Security acceptance requirements

English integration of the 32 requirements from the 2026-09-08 review, updated only where D-052–065/MC clarify them. Status: incorporated into the implementation backlog, **none certified implemented**. Requirements that change policy still depend on the named clarification/gate. Owner is the corresponding backlog domain team; QA/security verifies independently of the implementation assertion.

| ID | Scope | Requirement | Minimum acceptance evidence |
|---|---|---|---|
| SEC-01 | 001 | Normalize phone; enforce uniqueness; expire and atomically consume purpose-bound OTP challenges; never log OTPs. | Concurrent validation gives one successful challenge consumption; expired/replayed codes fail and no duplicate account appears. |
| SEC-02 | 001 | Share OTP quotas across instances by number/IP/context, with resend cooldown, bounded attempts, spend limits and non-enumerating responses. | Distributing calls across instances cannot evade quotas; provider failure authenticates nobody; abuse cannot permanently lock a victim out. |
| SEC-03 | 001/004 | Specify bounded sessions, silent refresh rotation, replay detection and revocation across every exposed access path. | Old access token fails after revocation; replay outside documented provider reuse exceptions terminates access; approved web/app concurrency policy passes. |
| SEC-04 | 001/012 | Require independent prior proof for risky recovery/number changes, reauthentication, audit and notification. | Lost/recycled phone and shared/unverified email never expose another account; delivery details alone cannot recover it. |
| SEC-05 | 003 | Require all-staff TOTP; single-use expiring invitations/reset; protected secrets; two named administrator recovery/bootstrap. | Expired/replayed invitation and inactive accounts fail; recovery works without a hidden account. |
| SEC-06 | all | Validate identity, permission and resource scope on every API/action/export/RPC/realtime channel; unknown permission denies. | Anonymous/client/other-client/five-role matrix passes direct calls, including forged cookies. |
| SEC-07 | 003 | Apply role changes/deactivation at next request; prevent self-escalation and forbidden role combinations. | Existing tokens lose removed rights; multi-role and role-edit attacks fail. |
| SEC-08 | 003/006 | Isolate staff origin with host-scoped Secure/HttpOnly cookies, CSRF/Origin checks and restrictive CORS. | Third-party origin cannot mutate; GET has no business side effect; cookie scope is verified. |
| SEC-09 | 003/011 | Scope drivers to assigned rounds/useful periods, preparation to picking/labels and support to necessary data. | Out-of-round IDs and oversized exports fail, including direct download endpoints. |
| SEC-10 | 011 | Model delivery confirm/fail/correct as audited server-time transitions with deduplication and separate correction permission. | Double tap/retry creates one effect; correction and reconfirmation do not credit referral twice. |
| SEC-11 | 001/003 | Type, bound, version and audit settings; reauthenticate sensitive changes; keep secrets outside business tables. | Invalid value fails; old rule version is recoverable; settings cannot reopen frozen days or disable an invariant. |
| SEC-12 | 002 | Check whole-day feasibility after hard filters for all units; block unresolved days with an alert. | All options excluded and two slots sharing one remaining dish produce a safe block; a new profile is rechecked. |
| SEC-13 | 004-food | Version ingredients/allergens; distinguish unknown from none; validate publication and analyze correction impact. | Removal never rewrites historical recipe; incomplete dish cannot publish. |
| SEC-14 | 002/011 | A new unsafe constraint after freeze creates a priority incident, stops affected preparation/handover and records resolution. | Frozen unsafe day is blocked; an administrative logistics exception cannot bypass the hard filter. |
| SEC-15 | all-time | Use server time and Africa/Casablanca with separate consumption, production and delivery dates. | Before/at/after cutoff, midnight, phone timezone and local time transitions pass. |
| SEC-16 | 010/011 | Serialize freeze and mutations, recheck at commit, preserve snapshots and append amendments. | Concurrent swap/freeze yields one coherent state; stale picking is rejected as current. |
| SEC-17 | 002 | Use idempotent version-aware generation jobs keyed by subscription/day/type/unit, with visible failure and retry. | Concurrent publication/payment does not duplicate portions; old job cannot restore excluded food. |
| SEC-18 | 004 | Use OS-protected session storage; no privileged keys in bundles/public env/logs/updates; purge account cache on logout. | Inspect signed iOS/Android builds and logs; switching accounts leaks no prior data. |
| SEC-19 | 004/006 | Use opaque expiring limited-use relay, no identity or health data in URL; authenticate before account reads. | Forwarded, expired and wrong-account links reveal no profile/order. |
| SEC-20 | 004/006 | No pre-authentication phone disclosure; normal login recovers installation with a lost relay. | Lost-link installation reaches the same account without second registration. |
| SEC-21 | 004 | Minimize, expire and partition offline cache; mark stale data; disallow offline business mutations. | Account switch has no cache leak; stale food assignments are not claimed current; reconnect checks revocation. |
| SEC-22 | 004/012 | Bind push tokens to installation/current session; detach on revocation; generic content and authorized retrieval. | Revoked phone receives no personalized data; notification history is owner-scoped. |
| SEC-23 | 007 | Use server-centime quotes bound to account/config/version; activate only after authenticated reconciled payment event. | Forged browser return, wrong amount/currency and duplicate webhook never cause invalid activation. |
| SEC-24 | 007 | Use opaque provider payment sessions and hosted/tokenized card input; no PAN/CVV in Fitnest; separate test/prod keys. | Inspect requests/logs; application failure after charge remains reconcilable. |
| SEC-25 | 007/010 | Renewal/cancel/retry have explicit states, due-date deduplication, acceptance evidence and compensation. | Cancellation race is deterministic; timeout/retry never charges twice. |
| SEC-26 | 001/007 | Enforce append-only unit-separated ledger, transactional balance, unique business source and frozen redemption price. | Concurrent spends cannot overspend; actual application role cannot UPDATE/DELETE/TRUNCATE ledger. |
| SEC-27 | 001/011 | Atomically enforce first delivery, referral cap and self-referral exclusion; retain phone-history eligibility without treating phone as permanent person. | Two first events create one reward; at cap-minus-one two referrals issue at most one; correction/replay and number history pass. |
| SEC-28 | 012 | Use transactional outbox, bounded retries, authenticated callbacks, event/recipient/channel deduplication and failure alerts. | WhatsApp outage duplicates neither delivery nor credit; invalid callback rejected; no health data in notification content. |
| SEC-29 | 001-foundation | Separate application/migration DB privileges; validate all exposed tables/views/RPC/realtime, including legacy; no privileged client keys. | Use actual roles against server and direct Supabase interfaces; cross-account reads/writes and revoked sessions fail. |
| SEC-30 | all | Restrict business audit; pseudonymize technical IDs; redact tokens/OTP/phone/health; audit exports. | Failure samples have no secrets; support cannot read outside scope; export has actor evidence. |
| SEC-31 | ops | Separate environments/secrets; use synthetic test data; test backup restore and erasure handling. | Restore in isolation does not contact live providers; deletion requests are reapplied. |
| SEC-32 | release | Mandatory CI, locked dependencies, secret/code/dependency checks, protected signing and old-client API compatibility. | Old mobile client cannot bypass server rules; artifacts trace to commit and rollback is demonstrated. |

All 32 IDs must have a backlog owner and an acceptance reference. Tests run against real local/staging services where the guarantee concerns transactions, roles, auth or provider callbacks; mocks alone cannot prove those guarantees. The provider's refresh replay exceptions must be tested, not treated as an unconditional every-reuse failure.
